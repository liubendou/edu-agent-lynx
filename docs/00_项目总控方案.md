## 3. 多级校验机制

- L1 子智能体自验：交付前自跑构建/测试，报告须含实际执行的验证命令与结果
- L2 总控抽验：逐文件核对交付物与任务书边界；构建/测试命令复跑
- L3 交叉评审：关键里程碑（M1/M3/M7）由独立评审子智能体对照 PRD/UID 出评审报告
- L4 用户裁决：范围变更、外部依赖（API Key）、不可逆操作前必须升级用户

## 4. 冲突与依赖管理

- 契约先行：M2 全体以 M1 的 `CONTRACTS.md` 为唯一接口依据；改契约须走变更记录
- 并行边界：M2 内各工作流目录互斥，禁止跨目录写
- 事实源唯一：两份方案 + skill/ 只读；任何子智能体不得改写
- 复用优先（用户规则）：FSRS→ts-fsrs；手势→lynx-ui Swiper/Draggable；动效→@lynx-js/motion；列表→FeedList；TTS/ASR→sherpa-onnx；禁止自研同类轮子
