### 2.2 集成缺口申报：isDue 修复（本报告最重要发现）

**问题**：硬规则 2 出卡入队的首复卡由 `createEnqueuedState` 产出——FSRS 态 = New、due=T+1。而 `domain/queue.ts isDue` 原实现 `state !== New && due ≤ now` 把 New 态一刀切排除，导致**出卡 T+1 永远不会进入复习决策**（既非 due、又因已有 learned_once 状态不属新学候选）——"出卡→次日复习"核心闭环在决策层断裂。既有 340 测试未覆盖此旅程（既有测试的到期卡均为直接构造的 Review 态夹具），由本次 M7 验收测试旅程②首先暴露。

**修复**（1 处判断）：`enqueued = state !== New || status === 'learned_once'`——已入队（learned_once）的 New 卡按 due 正常到期；未入队（unseen/seen）状态仍不产生欠账，硬规则 1 语义不变。修复后 344 用例全绿（含 domain-queue 全部既有用例），无回归。

**定性**：属"集成验收发现并修复的缺陷"，超出任务书清缝四项边界，故单独申报请总控/用户知悉；如不认可可单点回退（但旅程②验收用例将随之失败）。

1. **安装**：`adb install -r android/app/build/outputs/apk/release/app-arm64-v8a-release.apk`（arm64 真机；armeabi-v7a 老设备同法）。debug 签名允许直接覆盖安装。
2. **冒烟步骤（建议顺序）**：冷启动（骨架→首启文字→《学习科学》小课入口）→ 开始小课走完 quick 流程 → 回首页（今日计划面板）→ 新学 meta-001 走 standard 至出卡提示 → 我的页配置项可见 → 成长页有柱子 → 改系统日期 +1 天重启 → 首屏"今天有 2 张要还" → 复习：答对→撤销条→模糊（再讲一遍）→答错（自动补讲 90s）→ 收尾卡。
3. **KV/Native 桥**：StorageModule 真机读写与重启保持（内存 KV 已测，Native 桥待真机）。

## 7. 已知限制与风险

1. **isDue 修复**（§2.2）：超出清缝清单的最小必要修复，已申报；语义收窄为"已入队卡才可到期"，344 用例无回归。
2. **APK 体积**（87.6/61.2 MiB）：minify=false（R8 对 Lynx bundle 反射加载与 sherpa-onnx JNI 的 keep 规则未经验证，V1 体积换确定性）+ sherpa-onnx AAR 占大头。V1.x 开 R8 需补 keep 规则并真机回归。
3. **debug 签名**：仅测试分发，不可上架；正式发布前必须换独立 release keystore（build.gradle.kts 已注明）。
4. **web_search 无内置后端**：产品语义即"用户自配端点"（§7.3 可配置后端裁决）；未配置返回 not_configured 业务失败不抛错。
5. **云侧实流未验**：CloudClient 真实流式路径仅有契约级测试 + Mock 覆盖；真 Key 行为（含缓存命中与升级实发）待 §6.3 第 9 项。
6. **真机性能/手感全部待实测**：§6.2/6.3 各项，本报告不预设结论。
7. **既有测试唯一改动**：tools-registry.test.ts web_search 未配置断言 not_implemented→not_configured（清缝清单第 3 项要求的语义变更，单行适配，测试意图不变）。
8. **首启灌库时机**：灌种子只写 ALU 主数据不产生用户记录，故灌库后首启判定仍成立（引导文案/小课不跳过）——语义经旅程①断言固化；旧库（已有数据）幂等不覆盖。
